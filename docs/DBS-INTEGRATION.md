# 与 dbs 技能的配合（四步）

dbs 是一组**提示词型**技能，不能被命令行直接调用。所以拆分处理：能脚本化的落成脚本，不能的变成必过清单。

## 四步分工

| 步骤 | 时机 | 谁做 | 输出 |
|---|---|---|---|
| `dbs-content-value` | 动笔前 | 人 | 这篇会吸引谁？值不值得写？ |
| `dbs-content` | 动笔前 | 人 | 选题怎么组织成一条判断链 |
| `dbs-ai-check` | 初稿后 | 脚本 + 人 | 22 条 AI 特征；脚本查 8 条可量化的 |
| `dbs-resonate` | 初稿后 | 人 | 核心主张是否单一？哪句读者会走？ |
| `dbs-content-risk-check` | 定稿前 | 脚本 + 人 | 7 类风险面；脚本扫，逐句判断人做 |
| `dbs-plain-writing` | 按需 | 人 | 产品 / 功能说明类内容平铺直叙 |

## 脚本能查的部分

```bash
node tools/dbs_check.mjs article.md
```

| 检查 | 对应特征 / 风险 | 阈值 |
|---|---|---|
| 「不是X是Y」密度 | AI #8 | 每 800 字 >3 次 → error |
| 全文无犹豫/边界 | AI #9 | 500 字以上无一处 → warn |
| 连接词过密 | AI #17 | 每千字 >6 处 → warn |
| 翻译腔 | AI #19 | 「作为一个 / 进行了一个 / 的的」等 |
| 祝福式结尾 | AI #21 | 结尾「你值得 / 愿你」 |
| 替读者立靶 | AI #7 | ≥2 处 |
| 主动堵反驳 | AI #1 | ≥3 处 |
| 节奏过于均匀 | AI #14 | 连续段落长度接近 >30% |
| 发布风险 | 风控 | 外链 / 联系方式 / 长数字 / 敏感词面 / 绝对化 / 医疗 / 投资 |

退出码：`0` 无 error / `1` 有 error。

## 阈值来自哪里

阈值不是拍脑袋，来自 `dbs-ai-check` 的「误伤警告」一节：

- 「不是X 是Y」：800 字内 3 次以上才算信号（更低密度是正常修辞）
- 替读者说蠢话：虚构的读者声音明显被矮化才算
- 收束金句：只适用公众号长文，短视频段段金句是体裁要求

## 关键立场

**识别 AI 特征 ≠ 帮人伪装成人类。**

脚本命中不等于必须改；人写也会触发。脚本只负责把可疑处指出来，判断留给作者。
